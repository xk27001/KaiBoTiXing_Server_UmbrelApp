## 产品概述

对抖音主播开播监控软件进行 4 项功能改造：新增「弹窗提醒」「日志记录」两个可控开关，移除不再需要的 monitor_record 爬取记录，并新增开播会话表记录主播的开播/关播时间与时长。

## 核心功能

1. **弹窗提醒开关**：顶部栏新增「弹窗提醒」复选框，开启时开播弹窗+声音提醒，关闭后两者均不触发；开关状态持久化到数据库。
2. **日志记录开关**：顶部栏新增「日志记录」复选框，开启时业务日志写入数据库（monitor_log），关闭时只保留本地日志文件（logback），不写数据库；开关状态持久化。
3. **移除爬取记录**：删除 monitor_record 相关实体、DAO 及写入逻辑，并 DROP 数据库中的 monitor_record 旧表和数据。
4. **开播会话记录**：新增 anchor_live_session 表，记录主播每次开播的开始时间、关播时间及开播时长（秒）。

## 技术栈

- Java 25 + JavaFX 23.0.2（沿用现有）
- MySQL + 纯 JDBC DAO 层（沿用现有 MonitorConfigDao.get/set 存储开关）
- 现有分层架构：ui(MainController) / service / dao / scheduler / model / util

## 实现方案

### 1. 开关持久化与传递

开关配置存入 `monitor_config` 表（key-value），复用 `MonitorConfigDao`：

- `alert.enabled`（1/0，默认 1）
- `log.enabled`（1/0，默认 1）

传递链路：

- `MainController` 构造时读取两个配置的初始值，初始化顶部栏两个 `CheckBox`。
- `LogService` 增加 `boolean logEnabled` 字段 + `setLogEnabled(boolean)`，在 `write()` 中判断：`logEnabled == false` 时跳过 `logDao.insert(entry)`，但仍执行 slf4j 文件日志。
- `MonitorScheduler` 增加 `boolean alertEnabled` 字段 + `setAlertEnabled(boolean)`，在开播边沿处判断：仅当 `alertEnabled == true` 才调用 `alertService.alert(...)`。

### 2. 弹窗提醒开关（需求1）

- `MainController.buildTopBar()` 新增 `CheckBox cbAlert = new CheckBox("弹窗提醒")`。
- 初始值从 `MonitorConfigDao.get("alert.enabled", "1")` 读取。
- `setOnAction` 中：`scheduler.setAlertEnabled(cbAlert.isSelected())` 并 `configDao.set("alert.enabled", want ? "1" : "0")` 持久化。
- `MonitorScheduler.crawlOne()` 开播边沿逻辑改为：

```java
if (current == LiveStatus.LIVE && previous != LiveStatus.LIVE) {
sessionDao.insertSession(...);  // 记录开播会话
if (alertEnabled) {
alertService.alert(anchor.getNickname(), result.roomId());
}
}
```

### 3. 日志记录开关（需求2）

- `LogService.write()` 中，在 `logDao.insert(entry)` 前加判断：

```java
if (logEnabled) {
logDao.insert(entry);
}
```

- slf4j 文件日志（`log.info/warn/error`）始终执行，不受开关影响。
- `MainController` 顶部栏新增 `CheckBox cbLog = new CheckBox("日志记录")`，切换时 `logService.setLogEnabled(...)` + `configDao.set("log.enabled", ...)`。

### 4. 移除 monitor_record（需求3）

- 删除文件：`src/main/java/com/kaibotixing/dao/MonitorRecordDao.java`、`src/main/java/com/kaibotixing/model/MonitorRecord.java`。
- `MonitorScheduler.java`：删除 `recordDao` 字段、`import MonitorRecord`、`import MonitorRecordDao`，以及 `crawlOne()` 中构造 `MonitorRecord` 并 `recordDao.insert(record)` 的代码块。
- `schema.sql`：删除 `CREATE TABLE monitor_record (...)` 语句。
- `DataSourceManager.initSchema()` 末尾追加执行 `DROP TABLE IF EXISTS monitor_record`（幂等），删除已存在的旧表和数据。

### 5. 开播会话记录（需求4）

新增实体与 DAO：

- **`model/AnchorLiveSession.java`**：字段 `id`、`anchorId`、`nickname`、`startTime`、`endTime`、`durationSeconds`。
- **`dao/AnchorLiveSessionDao.java`**：
- `insertSession(long anchorId, String nickname, LocalDateTime startTime)`：插入新会话（start_time=now，end_time=NULL）。
- `closeSession(long anchorId, LocalDateTime endTime)`：查找该主播最近一条 `end_time IS NULL` 的会话，回填 `end_time=now`、`duration_seconds=TIMESTAMPDIFF(SECOND, start_time, end_time)`。

新表结构（schema.sql 中新增）：

```sql
CREATE TABLE IF NOT EXISTS anchor_live_session (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    anchor_id       BIGINT        NOT NULL COMMENT '主播ID',
    nickname        VARCHAR(100)  DEFAULT NULL COMMENT '主播昵称快照',
    start_time      DATETIME      NOT NULL COMMENT '开播时间',
    end_time        DATETIME      DEFAULT NULL COMMENT '关播时间',
    duration_seconds BIGINT       DEFAULT NULL COMMENT '开播时长(秒)',
    KEY idx_anchor_start (anchor_id, start_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='主播开播会话记录表';
```

会话记录逻辑（`MonitorScheduler.crawlOne()` 中，利用已有的 `lastStatusMap` 边沿检测）：

- 开播边沿 `current == LIVE && previous != LIVE`：`sessionDao.insertSession(anchor.getId(), anchor.getNickname(), now)`。
- 关播边沿 `previous == LIVE && current != LIVE`：`sessionDao.closeSession(anchor.getId(), now)`。
- 会话记录独立于「日志记录」开关，始终记录（需求4明确要求记录业务数据）。

## 实现细节

- 会话时长计算在 SQL 层用 `TIMESTAMPDIFF(SECOND, start_time, ?)` 完成，避免 Java 端时间运算误差。
- `closeSession` 只更新最近一条未关闭的会话，保证幂等性。
- `MonitorScheduler` 构造函数签名保持兼容（内部新增 `sessionDao` 字段，无需改 MainController 调用）；`setAlertEnabled` 为新增公开方法。
- `DROP TABLE IF EXISTS monitor_record` 放在 `initSchema()` 建表逻辑之后，保证每次启动幂等清理。
- 开关 CheckBox 的初始状态在 `MainController` 构造后、`buildTopBar()` 时读取，避免空指针。
