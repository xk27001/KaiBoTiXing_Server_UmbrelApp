## 产品概述

对现有抖音主播开播监控软件进行 5 项功能优化与缺陷修复，提升界面正确性、刷新实时性、使用便利性与配置持久化能力。

## 核心功能

1. **修复表头重复显示**：主播管理、监控状态两个表格的表头列目前重复显示了 2 遍，需去除重复，恢复正常单列表头。
2. **监控状态 5 秒自动刷新 + 开播置顶提醒**：监控状态页每 5 秒自动刷新一次；检测到主播由未开播变为开播时，弹窗置顶显示并播放提示音。
3. **开机自启动 + 自动开启监控**：增加开机自启动开关，启用后随系统登录自动启动软件，且启动后自动开启监控调度。
4. **修复日志时间显示与刷新**：修复日志时间列显示空白问题；日志页初始化即加载历史日志，并随 5 秒刷新周期自动更新。
5. **表头列宽持久化**：用户手动调整各表格列宽后自动保存，下次启动恢复，无需重复调整。

## 技术栈

- Java 25 + JavaFX 23.0.2（沿用现有技术栈）
- Maven 构建，jpackage 打包 exe（沿用现有方案）
- MySQL + monitor_config 表（复用现有 MonitorConfigDao.get/set 存储列宽与自启动开关）
- javafx.animation.Timeline 实现 5 秒周期刷新
- Windows 注册表 Run 键实现开机自启动

## 实现方案

### 1. 修复表头重复显示（问题1）

**根因**：`MainController.getRoot()` 中 `buildAnchorTab()`/`buildStatusTab()`/`buildLogTab()` 被调用两次，导致 `columns.addAll` 重复执行。

**方案**：删除 `getRoot()` 中第 84-86 行的冗余调用，仅保留 `new Tab("xx", buildXxxTab())` 内的调用。同时将三个 `buildXxxTab()` 返回值缓存到字段，避免未来重复调用。

### 2. 监控状态 5 秒刷新 + 开播置顶提醒（问题2）

**方案**：

- 在 `MainController` 中新增 `Timeline`（周期 5 秒），周期性调用 `refreshAnchors()` 刷新状态列表，并刷新日志列表。
- 定时器随界面构建启动，`shutdown()` 时停止。
- `AlertService.alert()` 中为 `Alert` 增加 `setAlwaysOnTop(true)`，确保弹窗置顶；声音提醒逻辑已有，保持不变。
- 开播边沿检测逻辑（MonitorScheduler 中已有）保持不变，仅增强提醒呈现方式。

### 3. 开机自启动 + 自动开启监控（问题3）

**方案**：

- 新增 `service/AutoStartService.java`：
- `isExeEnvironment()`：判断当前是否以 exe 运行（读取 `System.getProperty("jpackage.app-version")` 或 `java.class.path` 是否指向 exe 内部路径）。
- `enable()`/`disable()`：写入/删除注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，键名 `KaiBoTiXing`，键值为 exe 绝对路径 + `--auto-start` 参数。
- `isEnabled()`：查询注册表判断当前是否已启用。
- `Launcher.main` 接收 `--auto-start` 参数，透传给 `MainApplication`（可通过 `getParameters()` 或静态标志）。
- `MainController` 构造或初始化时检测 `--auto-start`，若存在则自动调用 `scheduler.start()`。
- UI 顶部栏增加「开机自启动」`CheckBox`，勾选/取消时调用 `AutoStartService.enable()/disable()`，状态初始值从注册表读取；jar 环境勾选时给出「仅 exe 版本生效」提示。

### 4. 修复日志时间显示与刷新（问题4）

**方案**：

- `LogService.write()` 中 `new MonitorLog(...)` 后立即 `entry.setCreateTime(LocalDateTime.now())`，使推送给 UI 的日志条目带有时间戳。
- `MonitorLogDao.insert()` 保持 `create_time` 由 DB 默认值填充（不影响），但可同步回填 `log.setCreateTime`。
- `MainController` 日志 Tab 构建时调用 `refreshLogs()` 加载历史日志。
- 5 秒定时器同时调用 `refreshLogs()`，实现日志自动更新（与状态刷新共用同一个 Timeline）。

### 5. 表头列宽持久化（问题5）

**方案**：

- 新增 `util/ColumnWidthStore.java`（或作为 MainController 内部方法）：
- `save(TableView, tableKey)`：遍历列，将每列宽度保存到 `monitor_config`，key 形如 `ui.col.{tableKey}.{index}`，value 为宽度数值。
- `restore(TableView, tableKey)`：从 `monitor_config` 读取各列宽度并设置。
- 三个表格（anchorTable、statusTable、logTable）在列添加后调用 `restore` 恢复宽度。
- 为每列 `widthProperty` 添加监听（带防抖，如 300ms 后写入），用户调整后自动保存。
- 保留 `CONSTRAINED_RESIZE_POLICY`，但列宽恢复与保存仍能生效（恢复在布局后应用，保存监听当前实际宽度）。

## 实现细节

- 5 秒刷新使用 `Timeline` + `KeyFrame(Duration.seconds(5))`，`setCycleCount(INDEFINITE)`；在 `shutdown()` 中 `stop()`。
- 列宽持久化写入需防抖，避免每次像素变化都写数据库；采用 PauseTransition 或手动计时器。
- `AutoStartService` 使用 `java.util.prefs` 或直接 `reg` 命令/`Advapi32Util`（JNA）；为减少依赖，优先用 `Runtime.exec("reg add/delete ...")` 或 `java.util.prefs.Preferences`（Preferences 映射到 HKCU 的 JavaSoft 下，需确认 Run 键路径，建议直接用 reg 命令最可靠）。
- 所有 UI 更新通过 `Platform.runLater` 切回 FX 线程。
